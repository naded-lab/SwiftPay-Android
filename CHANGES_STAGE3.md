# SwiftPay — Stage 3 changes

## Added
- Native USSD execution remains based on Capacitor `UssdDialer` and Android `TelephonyManager.sendUssdRequest`.
- Jawwal Pay balance card on the home screen.
- Automatic extraction of a balance amount from common Arabic/English currency response patterns.
- Raw USSD response viewer for cases where automatic extraction is not possible.
- Dual-SIM selector using the existing native `listSims()` API.
- Selected SIM is stored locally and reused for USSD balance checks and transfers.
- Busy-state protection while a USSD request is being executed.
- Basic USSD input validation in the native plugin.
- Automated Stage 2 installation script that copies/registers the native plugin and adds required Android permissions.

## Important
- The balance command is currently `*110*3#` as specified in the existing project.
- The exact wording returned by the carrier can vary. If the carrier changes the response format, the UI keeps the raw response visible so the parser can be adjusted without changing the USSD engine.
- The project remains offline-first and continues to use localStorage; no server/database is introduced.
- This archive is source code. The `android/` directory is generated by Capacitor during `setup.sh`, then patched automatically by `native-stage2/install-stage2.sh`.
